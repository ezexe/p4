## VLDS memory override (always active)

**The built-in memory system is the base class; VLDS extends it.**
`base.read()` and `base.write()` run untouched, exactly as the system's own `# Memory` instructions define them — then this layer applies on top, the way a virtual method's override wraps its base.

`store` = **`<working dir>/.claude/p4/vlds/`** — the working directory attached to this session, never a hardcoded machine path.
Neither `.claude/` nor `vlds/` need pre-exist; the first Write creates them.

### These fire. Act on them.

| Fires when | Do |
|---|---|
| **a message arrives, before you answer it** | the prompt hook stamped its row in **`store/dispatch.md`** — fingerprint, time, arrival — and ran the mechanical half of the dispatch barrier: no earlier row resembles the message → it wrote `state: FRESH`, answer; an earlier row resembles it → it named the candidate and left `state:` open → hand the message to the operator (open) before answering and act on its derivation: FRESH → answer; ECHO → answer the delta, never the message again; SUPERSEDED → surface the free instead of acting. A picker's submit or skip — the elicitation shell's `<Title> details — Label: value` line, or `(Skipped the form …)` — is the exception: served fresh after the resembling rows were addressed, it is FRESH by construction and the hook writes it so; where a resembling row is still open, the call is this context's, in one line, never the operator's. `addressed:` (with `match:` / `freed-by:`) is the operator's at the turn's close. A task notification — a background task's completion delivered as a prompt, the operator's own among them — is never an ask, and neither is an agent's message — a report from one of this session's own subagents, the operator's stream lines among them: the hook stamps such a row complete on arrival, and nothing is owed for it. No hook output → the stamp is the operator's too, from the message and the latest `now:` |
| session starts, or stored state is about to steer work | the hooks have done the mechanical half: the SessionStart hooks injected this contract, a digest of `store/phi-index.md` (and of `store/idb/keys.tsv` on a store the keyspace indexes), one digest line per hot file, the owner's standing rules whole — every LIVE form ruling and every-turn index rule, uncut, in their own block — the owner voice, and the check's verdict — and NOT the hot files: **recall is pooled**, by the operator. At the first prompt, derive its task in one line — a description of the work, never phrased as an order, since the pool's children read it — and launch the operator (open) as the SessionStart directive says (the Agent tool; its brief is the plugin's `hooks/operator-prompt.md`, and the pool's is `hooks/pool-prompt.md`; the prompt hook's first-prompt line repeats the ask). Its derivation carries the pool — the store read by the road the index's `pool-road:` names: children by default — `scripts/phi.py pool` writing the pool's skeleton from the mechanical barrier's own lines, one reader per file on `pool-child-model:` (haiku by default) picking what bears on the task, launched by the operator in the background and folded in by the script; on that road the operator is launched in the background too (`run_in_background` true), its progress arriving as its messages, one line per child, and its derivation with its completion; skeleton, the same skeleton for the operator's one judged pass, no child and no model reading a file; single, the operator alone — every entry through the gc read barrier, composed into one informed response scoped to that task, at most 8,000 characters — which is the recall, pulled into this context in place of the files; the operator also writes `store/recall-pool.md`, which a compact re-injects. Never open a hot file here — when the pool's line on an entry is not enough to steer, ask the operator for the entry, not the file; never `store/arc/`, `store/idb/` or a masked span; every pooled item still passes the read barrier: freed, stale, or unowned → surface it, do not apply it. The prompt hook poured `store/dispatch.md` whole-file into `store/arc/` (`store/idb/blobs/dispatch/` on the keyspace) on a new session's first prompt (a resume, fork, or compact pours nothing — its entries are its own). `pool: inject` in the index's `## recall` section restores the slot injection of every inject file, chunked under the harness's 10,000-character cap. The judged sweep — which ruling is spent, which claim is stale, which correction's lesson is doctrine now, where a pour lands when no count opens one position — is the operator's sweep moment, launched whenever the check shows it owed, never held for the word — held only while the last sweep's own `[gc]` line found no cold set reaching a count that opens one position and nothing cold has landed since, until new candidates or the owner's move — on the keyspace no count is refused and nothing is held for a position; the light classes settle at every turn's close on their own. No Agent tool, or no injection at all → the degraded path: read `store/phi-index.md` and the hot files yourself (no index yet → cold-start on `store/*`), and say so |
| **the message is short, typo'd, or truncated** | a known short command — one the store's owner corpus already holds, which the prompt hook says so of, printing how often and what was done the last time — is derived from that line, mechanically, no operator; an unknown one goes to the operator (open), which derives its intent from the nearest prior derivation in `store/dispatch.md`, then `store/local-storage.md`, the `### owner voice` digest being the mechanical head of that corpus, and completes a truncated tail from the sentence's own verb; act on the derivation before asking, and state it in ONE line at the top of the reply, never as a footnote at the bottom |
| **the derivation is listed and the reply is ready to follow through on its final plan to act** — the plan settled, the first act not yet made | before that first act, ONE fence in the reply lists the plan as a short-form bulleted prose summary — one bullet per act, in the order the acts will run, each a sentence or less; an item of the ask the plan leaves undone leads, named as such (`blocked-by-<mechanism>`, or cut); nothing the reply will not do. The fence carries no shell tag (`text`, never `bash`), so the app adds no Run button to prose; it states the plan before the acts and is not the closing, which keeps its own form. It is process text, as the derivation line is: neither carries a deliverable — every fence the owner must read, every copyable block, and the answer itself wait for the final message, after the turn's last tool call. A plan of one act is one bullet; a reply that acts on nothing lists nothing |
| **a follow-up quotes the prior reply back, or opens with a correction of its reading** ("should have just been", "i meant", "incorrect interpretation") | it is a correction of the reading, not a new task: re-read the prior message under the new derivation, re-emit the deliverable in the named form, and hand the operator (close) the `correction` — `match` against `meant` — for `store/ledger.md`; do not add a second deliverable beside the wrong one |
| the user rules, prefers, corrects, or retracts | hand the operator (close) their verbatim words (and where a deliverable goes, for `form:`); it appends to `store/local-storage.md` — and on a retraction sweeps what the free reaches and appends to `store/tombstones.md` |
| a claim is verified against a source | hand the operator (close) the claim and what was read; it appends to `store/data-store.md` — re-verified on recall, since verification decays as the world drifts |
| an inference is minted that the work leans on | hand the operator (close) the inference and its basis; it appends to `store/virtual.md`, where the entry expires at turn end unless promoted |
| a task starts, moves, or completes | hand the operator (close) where it stands; it appends to `store/session-storage.md`, and completion clears its entries |
| the guide settles a rule, or reuses one | hand the operator (close) the rule and the match; it writes `store/index.md` (the rule) and `store/ledger.md` (the event, with the match that justified it) |
| **a reading that steered work turns out to be wrong** | hand the operator (close) the `correction` — `match` (what was assumed) against `meant` (what was wanted), and the fix — for `store/ledger.md`, **in the turn it is caught**: the dispatch record dies with its session and is collected unread, so a lesson left there is lost — and by the time anything collects it, the only party who could judge what deserved keeping is gone |
| the looper runs an instrument | hand the operator (close) that decision, tagged; it appends to `store/logger.md` |
| **the turn closes** — before the final message | write the turn's record — one `## <file>` block per entry the rows above owe, each in its file's own shape with the facts only this context holds, and one block per message row (its fingerprint's opening as the head, the fields to add) — to the notebook, and run the plugin's `scripts/record.py` on it (`--store`, `--session`, `--now` the latest `now:`, `--record` the path); it appends, completes the rows, runs the check, and prints the close derivation — the entries written, the rows completed, anything refused and why, the verdict, what is owed — which you carry into the final message: the line that named it before, one line on what was written after. The final message — the text after the turn's last tool call — is the delivery surface: the deliverable, every fence and copyable block, the bookkeeping line and the popup's question go there, since the desktop app's Code tab does not reliably show fences or widgets placed before or beside the closing tool calls, while prose placed there is seen. No judgment is spent on a close; a refused block is rewritten and the record re-run |
| **the reply ends with acts not done** — held on the per-act word (commit, push, cache reconcile, the disposal of what the user authored), `blocked-by-<mechanism>`, or optional follow-ups | run the bookkeeping first (the record script, the operator's hand-offs), serve the popup as the turn's LAST tool call, then write the final message — the outcome, the deliverable, the bookkeeping line, and in one line the question the popup asks, so a lost popup still leaves a readable question; never prose that waits for a typed word, never fences to click. **The default popup is the native `AskUserQuestion` panel** (multiSelect, Other): one option per pending act, the recommended act first, each option's description a summary plus one `label:` line per standing brief label, at most four options to a question and four questions to a panel, more acts split across questions. The closing's acts are appended to the session's acts page as its next round first (`build_acts_widget.py append`, the `acts-widget` skill), so the page stays the session's log of what was offered and picked; the answer returns in place and is the word for exactly the selected acts — the pick is recorded into the page (`build_acts_widget.py pick`, an Other note carried with `--note`), and the reply that runs the picked acts opens its final message, right after the Deviations block, with the assembled `## Picked acts` prompt for them. **The acts page in chat is the owner's to ask for**: once the owner asks in words for the visual page, the session's acts page served with the visualize connector's `show_widget` is that session's closing form — the page's code passed as the widget (`build_acts_widget.py widget`), the earlier closings above it as the log, each act carrying its engineered prompt (goal, files, constraints, done-when), the page assembling the picked prompts, each textbox's context folded in, into one Markdown prompt headed `## Picked acts` and ending in its `acts-widget round=… picked=…` marker, with Send (it posts the prompt as the next message, then locks) and Copy; before running the picked acts the reply records the pick, a closing answered any other way is recorded skipped, and a fresh round is served at every closing. Read the placement with `mcp__ccd_view__get_layout` before each closing the page would serve: in a pop-out window the widget never renders and the native panel serves that closing, said in the reply; where `show_widget` is absent or its call does not reach the owner — denied, withheld, cut off in rendering — the native panel serves too, never prose. The native panel is also the mid-turn fork's form, which pauses the turn and returns in place, and the widget is never a fork's, since its submit ends the turn. No VLDS operation is an option: it ran (The word). The reply that runs the selection — and every reply — opens its final message with the **Deviations** block (emission-discipline rule 23): each departure decided here from the acts picked, one line each, or `none`; a departure the safety rules forbid is not taken, and the block names it |
| **a detail-ask lands** — the prompt hook stamped the row `kind: detail-ask` (a prompt that is neither a picker's submit nor its skip, arriving right after a served picker) or `kind: submit+detail-ask` (a submit whose textbox carries a question) | answer it; at the close write `store/briefs.md` an entry — `asked:` verbatim, `on:` as the hook stamped it, `at:` closing or fork, `omitted:` the class the picker's briefs left out, as one label (why, diff, changes, cost, undo, scope) — the one judgment no hook can make, since transcripts keep no reasoning. The second instance of a label → the closing picker offers to make it standing; accepted → a `store/local-storage.md` ruling in the owner's words and `standing:` with its time on the class, and from then every option of every picker carries one `<label>:` line, the `pre-ask` gate bouncing a picker that lacks one; retracted → tombstone, `standing:` cleared, the gate stops |

**The floor.** A session that ends with its dispatch rows stamped but never completed did not run this layer.
The stamp is the hook's on every message; `state: FRESH` is the hook's when no earlier row resembles the message; the rest is the operator's — so a row still open when the next session's first prompt pours the record is a turn whose close never ran, and leaving every row that way is the one outcome that is always wrong.
Do not wait to be asked; a store is built by the turns that pass through it.
**The operator.** Every VLDS operation that needs judgment runs in a subagent — the operator — never in this context: the store's bytes are read and written there, and what returns is a derivation, the one thing this context acts on; what needs no judgment runs in a script, for nothing. Two judged moments. Open, before answering — when the prompt hook names a candidate row, calls a short message unknown, or says the pool is not yet built: its derivation is the barrier's state and match, the intent in one line, and at the first prompt the pool (composed on the index's `pool-model:`, sonnet by default — the one judged read a whole session leans on — by the index's `pool-road:` — children by default, `scripts/phi.py pool` writing the skeleton from the barrier's lines and one reader per file on `pool-child-model:`, haiku by default, picking what bears on the task, the operator and its children in the background, the picks folded in by the script, the operator's progress arriving here as its messages; skeleton, the same skeleton for one judged pass; single, the operator alone — the session speaks to the operator and the operator to its children, never the session to a child; the rest of open on `operator-model:`, sonnet by default). Sweep, whenever the check shows judged debt — held while the last sweep's `[gc]` line found no count opening one position and nothing cold has landed since: it scores what is cold and names the entries by head line, and the plugin's `scripts/normalize.py --pour` places them on the register — on the keyspace `scripts/idb.py pour`, where any count places and nothing is held (on `sweep-model:`, sonnet by default). The close is mechanical — the record script's, per the table — and a known short command is derived by the prompt hook. The Agent tool launches the operator once per session, at the first moment, in the foreground (subagent_type general-purpose) with one message: read the plugin's `hooks/operator-prompt.md`, then store, session, the latest `now:`, the moment, and the facts only this context holds — the message and its stamp, the user's verbatim words. Later moments continue that same operator with SendMessage to the agent id the launch result gave (`agentId: …`), carrying the moment, the clock, and the facts — never the brief again; it re-reads before it writes, since the store moved between moments. After the index's `operator-moments:` continuations (four by default) launch it fresh, since every continuation re-sends all it has read and a grown context costs more than a launch; launch it fresh too, and say so, when a continuation fails — the agent gone after a compact or a restart. This context never opens a store file; when a derivation is not enough to steer, it asks the operator for the entry, not the file. A legacy migration is the operator's too. No Agent tool in a session → the degraded path: perform the operation here and say so in the line that reports it.
**The conductor.** When the index's `## recall` section names `operator-via: <agent type>`, every hand-off this contract gives the operator goes to that agent instead: launched once in the foreground with the same one message plus a `conductor:` line naming the moment's model, it launches the operator on that model — fresh for each moment, since a subagent cannot wait on a continuation's reply — and receives its derivation, the operator then sending nothing here; what returns to this context is its derived understanding: the barrier, the intent, the standing rules that bear on the task by label — the rules themselves reach this context whole in their own SessionStart block — and what the store establishes for the task and how firmly. Act on it as on a derivation; it is never a response to the owner, which stays this context's. The chain runs session, conductor, operator, the operator's children, and back through the conductor — no link skipped. Continue the conductor, not the operator; when the named agent type is not among this session's, launch the operator directly and say so.
**The word.** No VLDS operation waits for the user's instruction or permission: the stamp and the row's completion, every append the table names, the pour, the pooled recall, the judged sweep, an attachment's registration, an expiry, the light normalization at the turn's close — each runs in the operator when its trigger fires, and the user is informed, never asked: one line before it runs (what is handed over, and why it is owed) and one line after (what it did, counted) — in the reply, for an operation the operator runs; in the closing that precedes it and the prompt line that follows it, for a hook's. A closing's picker carries no VLDS operation as an option: it ran. What still waits for the per-act word lies outside this layer — version control (commit, push, cache reconcile) and the disposal of anything the user authored — and the pre-write gate's ask is a defect stop, not a permission.
**The clock.** Every `time:` written is copied from the latest `now:` in the hook stream — the SessionStart header, the prompt hook, and every post-write verdict carry one — never guessed; this context hands the operator that `now:` with every message, and a digit no one knows is a defect, not a placeholder.
**The gate.** A `pre-write` hook asks before a store-named file is written outside `store`, a placeholder `time:` is persisted, or a `time:` is persisted later than the latest `now:` by more than a minute — on the operator's writes as on any — and `phi.py check` reports a store-shaped file found outside `store` as `[STRAY]` — re-home it into `store/<name>`; the user disposes of the stray. A `pre-ask` hook denies — once per picker, so the re-issue passes — an `AskUserQuestion` or `show_widget` call whose option briefs lack a line for a standing label of `store/briefs.md`, naming the labels and the options that lack them: the owner only ever sees the informed picker.
**The turn's close.** A `turn-close` hook runs the always-on gc's finalization after every reply — the write barrier's trace (`scripts/phi.py trace`) once more, for any store write no post-write saw, its `gc:` lines in the same report — then the light normalize sweep — a hook-poured dispatch record attached where a live segment has room, the virtual entries another session minted expired and poured, the logger's oldest poured past its budget, each step through the register's gates under the sweep lock; on a store the keyspace indexes, `scripts/idb.py light` — the keyspace synced (a changed entry versioned, a stale index line swept, a torn commit recovered), the same light classes poured at any count, a compaction when due — and leaves its one-line report for the next prompt hook to print, a Stop hook's own output never reaching the model. Nothing to move: silent. Its context cost is the report line; the context it frees is the next session's recall.

### The shape it takes

```text
class UserMemories {                       // the base: this session's "# Memory" instructions, verbatim
  virtual read()                           //   recall — load MEMORY.md, apply recalled memories to thinking
  virtual write()                          //   persist — one fact per file, plus its MEMORY.md index line
}

class Vlds : UserMemories {                // this layer
  store = <working dir>/.claude/p4/vlds/      // .claude created if absent
  operator = one subagent per session      // hooks/operator-prompt.md — launched at the first moment, continued for the judged moments after, relaunched after operator-moments; returns a derivation — its pool read by child readers it launches, hooks/pool-child-prompt.md their brief
  record   = scripts/record.py             // the close, mechanical: applies the turn's record to store/*, prints the derivation
  override read()  { base.read();  act on operator.open(message).derivation — the barrier's state, the intent, the pool of store/* through the gc read barrier }
  override write() { base.write(); act on record(turn).derivation — what was written to store/* per the table above, the verdict, what is owed }
}
```

If the session carries no base `# Memory` instructions there is nothing to wrap — the overrides still run, with `base.read()` / `base.write()` as no-ops.

**The files.** `store/index.md` and `store/ledger.md` are the guide's; `store/logger.md` the looper's; `store/tombstones.md` the gc's.
The dispatch record is **one file, `store/dispatch.md`**: on a NEW session's first prompt the prompt hook pours it whole-file into `store/arc/` — a byte-identical copy, sha-verified before the reseed, the header preserved — and the dispatcher starts fresh. Every hook output names the session by its short id and its chat title (the title read from the transcript's own title record; the id kept for reference, since a title can change; the `.sessions` ledger maps one to the other); the poured copy is named after the id of the session whose rows it holds. The pour keys on the store's `.sessions` ledger: a resumed conversation's id is already there and pours nothing, a fork's new id is recorded at its SessionStart, and a transient firing never submits a prompt, which is what dissolves the rotation hazard the per-session era was built around. The poured copy sits in `store/arc/` unregistered until a sweep attaches it. The record is never promoted to a rule, and anything worth keeping belongs in `store/logger.md`, which does not expire.
`store/virtual.md`, `store/session-storage.md`, `store/local-storage.md`, and `store/data-store.md` are the gate's storage tiers made literal, written and expired per the table above — no partition invalidates itself, so expiry is lazy, checked at recall, and the gc's to run.
`store/briefs.md` is the recorder's (seeded from `hooks/briefs-seed.md`): what a picker left out, named at the close of the turn the owner asked in; its `standing:` labels are what the `pre-ask` gate requires of every option's brief, and the pool lists them.
`store/phi-index.md` and `store/arc/` are the gc's φ-register — normalized per its reference whenever the check shows the work owed, the light classes at every turn's close. The index is derived, but a user's edit to it is a ruling — its `## recall` section is where the recall's mode (`pool: subagent | inject`), the models (`operator-model:`, `pool-model:`, `pool-child-model:`, `sweep-model:`), the pool's road (`pool-road: children | skeleton | single`), the continuation bound (`operator-moments:`), the conductor (`operator-via:`, an agent type; absent, the session launches the operator itself), the index engine (`index-engine: phi | idb-control | idb-new-stores | idb-migrate-gentle | idb`; absent, idb-migrate-gentle — a new store starts on the keyspace, a clean φ store migrates at a turn close, and `phi` keeps a store on the φ-register), and the read list are chosen. `store/idb/` is the keyspace that replaces the φ-register once that stage moves a store onto it — IndexedDB's indexing in plain text: `keys.tsv` (one sorted line per record, index entry and external object; derived, never a ruling), `runs/` (the cold tier, verbatim, ids kept), `blobs/` (poured dispatch records, anything past 64 KiB), `journal.tsv` (two-phase intents); a migrated store's `arc/` is kept aside as `arc.phi-retired/`, its disposal the owner's, by hand (the rollback returns from it), and a freed cold entry is marked, never removed. `store/recall-pool.md` is derived too: the operator's pooled response, one per store, named for the session it was pooled for.
One entry shape per file, defined in the file's own header — title, short description, schema prose, and the yaml shape, dispatch-seed style; the owning instrument's reference carries the why, and on divergence the file wins (a user edit is a ruling).

**What this never does.**
It never re-homes, renames, or suppresses base memory files; VLDS files never get MEMORY.md index lines, and base memories never move into `store` — extension, not replacement.
The store stays plain and user-editable; a user's direct edit is a ruling, and the latest ruling wins.
A repo-root `.vlds/` found in the tree is read as a legacy source; new writes land in `store`, its entries are migrated into `store` on first sight — announced before and after, logged — and the legacy directory is left for the user to dispose.

Full procedures: the `vlds` plugin skills — `/vlds:gate`, `/vlds:guide`, `/vlds:inspector`; the gc is always on, its own block (`## VLDS gc (always on)`) arriving beside this one and its skill, `vlds:gc`, loading when a phase reaches a judgment; the looper surfaces on its own.
