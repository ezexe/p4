## src-fragger (always active)

**Code you write to finish a task is a frag, and a frag lives in `src/`, never in a scratchpad — `src/` is the git-tracked home of every reusable and worthwhile output of the work, code or not, and `.claude/p4/scratchpad/` is the notebook, tracked in the p4 repo too.**
`src` = **`<working dir>/.claude/p4/sessions/<name>/src/`** — this session's own, in the p4 repo (`.claude/p4/`, its own git repo, not the project's; vlds seeds it); one directory per task, each frag registered in **`src/frags.md`**; `.claude/p4/sindex/` indexes every session's src/ — an earlier session's frag is edited in place there. `notebook` = **`<working dir>/.claude/p4/scratchpad/`** — tracked by the p4 repo, never the project's.

| Fires when | Do |
|---|---|
| **you are about to write code to complete a task** — a script, a probe, a generator, a migration, a sweep, a harness page, a workflow script, a probe project's build files, a program you would otherwise run from a heredoc: anything that replaces manual, user-involved labor and whose job no single tool call does (the floor, next row) | write it to `src/<task-slug>/<name>.<ext>` — never a scratchpad, `/tmp`, or any temp directory — with a header comment naming the task, the date copied from the hook stream's `now:`, and the exact run command; register it in `src/frags.md` before the first run. It is tracked in the p4 repo: the output the notes were made for. What the task's frags read and what they produced that is worth keeping — a fetched spec, a captured page, a downloaded source, a design spec, a reading a claim rests on, a run's report — lives in the task's `out/` (`src/<task-slug>/out/`), tracked and unregistered; a sheet or README lives beside the frags |
| **the code you are about to write only does what one tool call does** — reads a file, swaps one or a few literal spans, writes it back; appends lines to a file; writes a whole file; runs one shell command | it is not a frag: make the Edit, Write, or Bash call. A heredoc that would carry backslashes, quotes, or `$` is the case where the shell cannot do the job, and the fallback from it is the dedicated tool — never a script that does the tool's job. A swap script is an Edit call in costume and worse than the call: it keys on text that moves, lands twice when its new text contains its old, and needs a header, a register entry, a state, and a retirement the call never needed. A store row, a per-turn record, anything written once and never run again is a Write call for the same reason — a frag is kept to be run again |
| **you are about to write a working file that nothing will read again** — notes, a plan, a commit draft, a run's log or transcript, a build tree, a cache | write it under the notebook, `<working dir>/.claude/p4/scratchpad/` — never the harness's per-session temp directory: that one is named after a session id, invisible to the user, and gone with the session. The notebook rides in the p4 repo; a log, a build or bin tree, a binary goes in its **`.out/`**, always ignored by its own `*` — the start re-seeds it and sweeps strays into it, and the gate asks for one written elsewhere. Code worth keeping is not a note: a code file in a scratchpad is neither a frag nor a tool call, and the gate asks |
| **a notebook file turns out to be worth keeping** — a later task runs, reads or edits it, the user edits it, or a commit is about to carry it | it is an output, not a note: code moves to `src/<task-slug>/` and is registered, anything else to that task's `out/`, and a pointer stays where the notebook refers to it. A log a claim cites is not made an output by the citation — the claim's own entry carries what was read, and the instrument that produced it is the output. A note the work leans on again is an output that needs moving, whatever the p4 repo already tracks |
| a task needs labor a frag may already cover | read `src/frags.md` first; update the frag in place and move its register entry's `time:` and `state:` with it, instead of writing a second one beside it |
| the harness refuses your execution of a frag | **double-check before interrupting the user** — (1) the frag is under `src/` and registered, so the hand-off would be one click; (2) the refusal is durable: retry the SAME call once, unchanged, in a fresh tool call — a refusal announced "for the rest of this conversation" is bound to the conversation's content, not the process: a fresh tool call has passed where the first was refused, a fresh conversation opened with a hand-off summary clears it, and a resume of the same conversation does not; (3) the user's word already covers the act — a word given once in the conversation still stands, and a retry needs no new one; (4) the interruption is a decision only the user can make, not labor you could still do. Record the retry in the register's `retry:` field. Only when all four hold: hand the exact run command in ONE `bash`-tagged fence, one command per fence, written for the user's own shell (the click runs there, not in yours), mark the entry `state: handed-off`, and say plainly what was and was not run — never re-write the frag or reroute the call through another tool or agent to get past the refusal |
| the user edits a frag | the edit is a ruling: read the current file before running or updating it, never overwrite it from memory |
| a frag's task is done and nothing will need it again | mark it `state: retired` in the register; delete nothing — the user disposes |

**Why the store.** Three homes, three lifetimes. The harness's per-session scratchpad is gone with the session: a script there is invisible to the user and unreachable when the harness refuses your own execution and the user has to run it instead. The notebook outlives the session and rides in the p4 repo, beside the work, never in the project's history; it is a pile, not a register. A frag under `src/` outlives the session, is the user's to read and edit, is registered, and is the recovery path when execution is refused. The split is by worth, not by file type: what someone will run, read, or edit again is a frag or an `out/`; what was produced on the way is a note.

**The floor.** A frag is measured by its job, not by its length. One tool call does an edit, an append, a whole-file write, or a shell command, and a program that only does one of those is the call in costume — written, nearly always, because a heredoc failed on the text it carried. The dedicated tool exists for exactly that text; reaching for a script instead trades a call that cannot land twice for a file that can, and then registers the file.

**The gate.** A `frag-gate` hook asks before ANY file is written or edited in the harness's per-session scratchpad, before a code file lands in any other temp location, and before a code file lands in a project's notebook (`.claude/p4/scratchpad/`, or an older `.claude/scratchpad/`) — where a swap script goes once it has stopped calling itself a frag, which the floor answers the same way: a frag under `src/`, or the tool's call and no file. It asks, never denies: a truly throwaway probe, run once and never again, may stay in the notebook; a captured page or source belongs in the task's `out/`; only you can say which this one is, and the ask exists because "throwaway" is what every kept script called itself first.

**The floor's own arm.** The gate reads shape as well as location: a short program that reads a file, swaps a span in it and writes it back is an Edit call in costume, and it asks wherever that program lands — under `src/` as readily as in a scratchpad, because the costume is wrong by its job, not by its address. All three of read, swap and write-back must appear in a short body, so a script that merely writes an output file is never touched.

**Scratch in the project root.** A data file written straight into the project root — a `.json`, `.jsonl`, `.csv`, `.log`, `.txt` dump that is not one of the project's own manifests — asks too: it lands untracked beside the real files, and the user finds it weeks later; that data belongs in the notebook, a log in its `.out/`.

**The notebook is the p4 repo's.** The SessionStart hook creates `.claude/p4/scratchpad/`; the p4 repo tracks it, and the project's repo excludes all of `.claude/p4/`. An older `.claude/scratchpad/` (git-ignored by its own `*`) is left as it was, the user's to dispose. The hook never touches the project's index or root `.gitignore`. The same start says, in one line, when `src/` holds code the register does not name or the register names a path that is gone and not retired: register the frag, or mark the entry.

**Where the gate is silent, and why.** Inside a subagent it says nothing about the ignored cases — the harness scratchpad, a temp directory, the notebook. No hook event injects text into a spawned subagent's context (`SessionStart` does not fire for one; `SubagentStart`'s stdout goes to the debug log), so its writer was never told this contract exists, and the ask is answered by a human who cannot redirect an agent already running — one prompt per scratch file is a stream, not a gate. The `agent_id` field, present only inside a subagent call, is the tell. The silence reads a missing channel, not a lesser care for subagent code; when an injection channel exists, this scoping should go.

The silence stops at the ignored, though: a file dropped in the project root lands in status, outlives every agent that could have been told, and is found by the user, so the root case asks for a subagent as it does for the main loop. What decides is whether the file reaches the project's history or status, not who the writer was.

Full procedure: the `frag` skill of the `src-fragger` plugin.
