A session's files

p4-phi keeps one folder for each linked session, phi/sessions/<sessionId>/ in the store of the project its session tree lives in, under .claude/p4/. This page says what each file holds and how p4-phi hands it from session to session. The session tree page shows the moves that change them.

The session's folder

session.json

The app's fields for the session with its task, its parent session in spawnedFrom, its write set in fileSet, its owned paths in shard, and the marks p4-phi sets, such as forked, doneRetired, stale and anchorSeen.

turns.jsonl

One row for each finished turn, written at Stop. Each row carries the turn's delta: heads, the branch heads of the repositories it edited in and of its folder as <repo>@<branch> <sha8>; files, the files its edit tools changed; and marks, its notes since the turn before that begin deprecates: or replaces:, each with the paths it names.

notes.jsonl and reports.jsonl

The session's notes, each a claim with its source, and the reports of its workers. The reports of orchestrators go to phi/reports.jsonl.

log.jsonl

One row for each hook call: time, hook, said, the length of the text the hook returned, ms, and what the hook did. A hook of phi.py's that raised leaves a row with its error instead, while a check routed through the retrieval hooks that raises is passed over without a row.

session.md

The session as one page. phi/sessions.md is the same page for the orchestrators of the project, with their latest reports, and git ignores it.

held.md

What did not fit beside a prompt, whole, each piece under a ## <time> heading, up to 256 KB, after which the older half goes.

standing.md

The standing instruction a session was handed in full, one ## <name> section each, so that after a compaction one line can name it.

plan.json

The session's task list as the app's update_plan calls leave it, kept below.

.calls/

One empty file per check and tool call, <kind>-<tool_use_id>, so each check runs once for a call; files older than a day are removed. Git ignores the folder.

What fits beside one prompt

The cap

Claude Code shows a hook's added context up to 10,000 characters, so p4-phi keeps its own to 9,500. At a session's start the rules take what the other lines leave. At a message the room is 4,000 characters, or the whole 9,500 when the session was just handed its start background.

What does not fit

Each part that fits is kept whole, and the rest goes whole to held.md, with one line saying how many pieces and characters it holds and naming the first three by their opening words.

After a compaction

A session that was told its standing instruction gets one line instead, phi (p4-phi): this session's task is "…", ending with the path of standing.md; the rules built into p4-phi come again whole. After a clear the whole instruction comes again.

What sessions hand each other

The anchor

anchor.json in a parent session's folder, or phi/anchor.json for the orchestrators, holds for each live worker its latest delta, marks, owned paths, task list and parent step, and the parent's own marks, owned paths and task list. Its version goes up only when that content changes. It is made again at Stop, at each update_plan call, at phi.py shard and when a subagent is bound. The orchestrators' anchor holds no heads or files.

The rebase check

At every message, when the parent's anchor is newer than the version the session last saw, p4-phi hands it the other sessions' marks, each once, then their heads and files, in at least a third of the room. Notes that touch the session's task, open steps, owned paths or edited files come in full, and the rest by count with the pages that hold them. Before any tool runs it warns, under phi (p4-phi): stop before any tool runs., of each uncommitted file or owned path a newer mark names and each uncommitted file inside another session's owned paths. A session's first look takes what is there as seen.

A fork

A session the app records as a fork, or whose first message opens Task (from the session that started this one):, is marked forked. It gets the whole start background, without the slice a fresh worker gets, and p4-phi pins its own task, owned paths and parent step above the conversation it holds, gives it the built-in rules without the memories, and cuts its rebase marks to its owned paths.

A fresh worker

A fresh worker gets the tasks of the sessions above it and its parent session's step with the steps around it. When its owned paths or its task name paths, it also gets what its parent's anchor holds on those paths, and the rebase then hands it only later changes. With no path named it gets the notes of the sessions above it and the last turn of each sibling instead.

A stale session

A finished worker whose work a newer deprecates: or replaces: note supersedes is marked stale. Its outcome is kept as a replaces: note on its parent session, it drops out of the anchor and the routing, and it is told once that its work is superseded. A turn that ends after that clears the mark.

Task lists and background tasks

Step addresses

An orchestrator's steps are numbered 1, 2, 3, and a worker's are Y.1, Y.2 under its parent session's step Y: the rootStep set on it, else the step its task names, else the parent's open step whose words match best, else the parent's current step. A revision is read by the steps' words, not their numbers.

Background tasks

A Bash or PowerShell call run in the background, a background Agent call, a Monitor or a Workflow is kept as a task under the step in progress, with its heads, paths and words, or under loose when no step is. Its completion notice or TaskStop closes it. An open task under a step is flagged once when its head moved or a newer mark names its paths or shares its words.

The job gap

An open task older than its own timeout plus one hour is marked unknown and no longer flagged. One older than ten minutes is advised to finish rather than be stopped.

Checks and limits

Checks before a tool

p4-phi's checks ride on the retrieval hooks' entries: a start call passes the start advice, a worktree or a shell command the branch guard, an archive call the archive check, a message to another session the go guard, a shell command also the store guard, the restart check, the delegation check and the nudge, and an edit the nudge. The first check that answers decides, and one that raises is passed over.

The caps

A session three deep in the session tree, or one with eight live sessions of its own, is told to start no more. The caps are advice, said in the standing instruction and the task-list advice, and only the readings of an under-determined message refuse past them.

pathfilter.py

With phi.track on in p4.json, the session tree is committed to the store, and a git clean and smudge filter on phi/** writes this project's root as {project} in the committed files and back on checkout, in its slash, backslash, Git Bash and WSL forms.

Each entry is read from phi.py, relay.py, plans.py, hook.py and pathfilter.py of p4-phi, in ezexe/p4 under lbiza/plugins/p4-phi/scripts.
