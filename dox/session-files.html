A session's files

p4-phi keeps one folder for each linked session, phi/sessions/<sessionId>/ in the store of the project its session tree lives in, under .claude/p4/. This page says what each file holds and how p4-phi hands it from session to session. The session tree page shows the moves that change them.

The session's folder

session.json

The app's fields for the session with its task, its parent session in spawnedFrom, the files its brief says it covers in fileSet, its owned paths in shard, and the marks p4-phi sets, such as forked, doneRetired, stale and anchorSeen.

turns.jsonl

One row for each finished turn, written at Stop. Each row carries the turn's delta: heads, the branch heads of the repositories it edited in and of its folder as <repo>@<branch> <sha8>; files, the files its edit tools changed; and marks, its notes since the turn before that begin deprecates: or replaces:, each with the paths it names.

notes.jsonl and reports.jsonl

The session's notes, each a claim with its source, and the reports of its workers. The reports of orchestrators go to phi/reports.jsonl.

log.jsonl

One row for each hook call: time, hook, said, the length of the text the hook returned, ms, and what the hook did. A hook of phi.py's that raised leaves a row with its error instead, while a check routed through the retrieval hooks that raises is passed over without a row.

session.md

The session as one page: its title, files, notes, turns and workers' turns, each turn by its steps and report. It quotes no prompt, since a worker is pointed to its parent session's page and a parent to each worker's. phi/sessions.md is the same page for the orchestrators of the project, with their latest reports, and git ignores it.

plan.json

The session's task list as the app's update_plan calls leave it, kept below.

.calls/

One empty file per check and tool call, <kind>-<tool_use_id>, so each check runs once for a call; files older than a day are removed. Git ignores the folder.

What fits beside one prompt

The cap

Claude Code shows a hook's added context up to 10,000 characters; past that it saves the text to a file and passes the session the file's path and a preview of its first 2,000. p4-phi cuts nothing of its own at a session's start or at its first message, which hands it its start background: the lines that ask the session to act come first, so they fall inside the app's preview, and the rest follows whole. At every later message the room is 4,000 characters.

What passes the app's cap

p4-phi keeps no ceiling of its own beside a prompt and no page for what would pass one. Every part passes whole, and the parts that ask the session to act come first. Source, hooks.md, "JSON output": a hook's additionalContext is "capped at 10,000 characters", and over the limit "Claude Code saves the output to a file in the session directory. It replaces the output with the file path and a preview of up to the first 2,000 characters." The same section says "Claude Code doesn't ask Claude to read the file", so when the acting parts alone pass that preview, one line ahead of them asks the session to read the app's file before going on.

After a compaction

The rules built into p4-phi come again whole. The compaction's summary keeps the conversation, the session's own turns and the address book it was handed among it, so p4-phi hands neither again: only the book's entries that changed since the session last looked, with the path of book.md, since a summary keeps no exact id or path. After a clear, which keeps nothing, the start background comes with the session's own turns and the address book comes whole. Where a message about something else goes is said by the app's own hand_off_to_session and start_session tools, so p4-phi hands no instruction of its own for it.

What sessions hand each other

The anchor

anchor.json in a parent session's folder, or phi/anchor.json for the orchestrators, holds for each live worker its marks, owned paths, task list and parent step, and the parent's own marks, owned paths and task list. Its version goes up only when that content changes. It is made again at Stop, at each update_plan call, at phi.py shard and when a subagent is bound. It holds no heads and no files: each session that writes works in a git worktree of its own, so another session's heads and files are nothing to build on before the tree's orchestrator merges its branch. A turn's own row in turns.jsonl keeps them, for the session's outcome, its closing commits and the push line.

The rebase check

At every message, when the parent's anchor is newer than the version the session last saw, p4-phi hands it the other sessions' marks, each once, in a room of 4,000 characters. Notes whose words touch the session's task or open steps come in full, and the rest by count with the pages that hold them. Ahead of them, under phi (p4-phi): stop before any tool runs., come the warnings other code kept for the session, each once. No file or owned path of the session is held against another session's note or owned paths, and no overlap of two sessions' owned paths is told: the paths lie in two worktrees and name different files. A session's first look takes what is there as seen.

A fork

A session the app records as a fork, or whose first message opens Task (from the session that started this one):, is marked forked. It gets the whole start background, without the slice a fresh worker gets, and p4-phi pins its own task, owned paths and parent step above the conversation it holds, and gives it the built-in rules without the memories. No start p4-phi drafts or advises forks a session that writes from a plain checkout. The start tool's own text says use_worktree is for a fresh start alone and is rejected with a fork, and that a fork "from a worktree session gets a fresh worktree" and "from a plain checkout it shares the folder", so such a fork would write in its starter's files, and a call that makes one is asked about.

A fresh worker

A fresh worker gets the sessions above it by title, never their prompts, and its parent session's step with the steps around it. When its owned paths or its task name paths, it also gets the marks and the parent's notes that name those paths, and the rebase then hands it only later changes. With no path named it gets the notes of the sessions above it and the last turn of each sibling instead.

A stale session

A finished worker whose work a newer deprecates: or replaces: note supersedes, by its words on the worker's parent step, is marked stale. No path the note names is held against the worker's files or owned paths, which lie in its own worktree. Its outcome is kept as a replaces: note on its parent session, it drops out of the anchor and the routing, and it is told once that its work is superseded. A turn that ends after that clears the mark.

Task lists and background tasks

Step addresses

An orchestrator's steps are numbered 1, 2, 3, and a worker's are Y.1, Y.2 under its parent session's step Y: the rootStep set on it, else the step its task names, else the parent's open step whose words match best, else the parent's current step. A revision is read by the steps' words, not their numbers.

Background tasks

p4-phi records no launch of its own. The Stop hook's input lists the work still in flight as background_tasks, and each Stop keeps that list on session.json as backgroundTasks, with the time as backgroundAt. The restart check, the archive checks and the ledger read it there, since a PreToolUse input lists no running task, and an entry leaves it once its completion notice arrives or a TaskStop or KillShell call stops it. No archive is held for it: the archive tool itself refuses a session with live background work. A subagent the Agent tool starts stays a task of the step in progress, as the subagent warnings need.

Checks and limits

Checks before a tool

p4-phi's checks ride on the retrieval hooks' entries: a start call passes the start advice, a shell command the store guard first, which asks before a hand pull or push inside a store and names p4.py sync --push --p4 <store> and, for a started session, its tree's orchestrator as the session that runs it, then the branch guard, which asks before a started session lands work or moves a checkout it shares to another branch, then the restart check and the nudge, an archive call the archive check, a message to another session the go guard, and an edit the nudge. The first check that answers decides, and one that raises is passed over.

The caps

A session three deep in the session tree, or one with eight live sessions of its own, is told to start no more. The caps are advice, said in the task-list advice and the split advice, and only the readings of an under-determined message refuse past them.

pathfilter.py

With phi.track on in p4.json, the session tree is committed to the store, and a git clean and smudge filter on phi/** writes this project's root as {project} in the committed files and back on checkout, in its slash, backslash, Git Bash and WSL forms.

Each entry is read from phi.py, relay.py, plans.py, hook.py and pathfilter.py of p4-phi, in ezexe/p4 under lbiza/plugins/p4-phi/scripts.
