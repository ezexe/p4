Delegation

p4-phi delegates each piece of work to where Claude Code runs it best, so a session's own turn is never held by it. Choose a kind of task below, see where it goes, and step through the path its result takes back.

  • Workers do the writing.An orchestrator plans and lands. Each work step of its task list goes to a worker, which the session tree page shows. A puppeteer is the exception: its steps stay with it.
  • Subagents run in the background.A read across files goes to Claude Code's built-in Explore, and the plugin ships one of its own, p4-phi:check. Any session can start either.
  • Nobody waits in the foreground.The session that asked goes on or ends its turn. A completion notification brings the result in a later turn.

The task

p4-phi names where each step of an orchestrator's task list runs, and which steps the orchestrator keeps. Write one to see where.

On by default

Nothing has to be configured. The delegation rule and the plugin's agent work in any project the plugin is enabled in.

Nothing to set up

  • Every session is given the delegation rule at its start, as one of p4-phi's built-in rules beside act-don't-wait.
  • Explore and a background command are Claude Code's own, so the plugin ships no agent that searches and none that runs a command.
  • The plugin's agent is a file in its agents/ folder, so it loads with the plugin under the name p4-phi:check.

One key turns it off

  • Set phi.levels to false in the project's .claude/p4/p4.json.
  • The delegation rule is then left out, no step of a task list is named for a background subagent, and a worker is not told at its first message how to split its own work.
  • No key turns it on. Any value but false, or no key at all, leaves it on.
{
 "phi": {
  "levels": false
 }
}

A worker's model and effort

The start calls p4-phi's advice hands out carry an effort, and a model unless the worker keeps its parent session's. The kind of the step decides both, and the brief says them in one line, Model and effort: <model> at <effort> effort.

Kind of stepModelEffort
static: docs pages, a rename, a version bump and other mechanical work that names no codeclaude-sonnet-5-5medium
build: every other step, such as a change to behaviour or anything that names codethe parent session's ownhigh
design: a design or review stepthe parent session's ownhigh

A serial run takes the model and effort of its hardest step. A brief that names its own lines Model: and Effort: wins over its kind, and a fork takes neither, since the app gives a fork its parent session's. An effort above the parent session's own is not accepted, and phi.child_levels in p4.json sets each kind's defaults.

What each behaviour rests on

Each mechanism is Claude Code's own, and the plugin only says when to use it. The sentence of the Claude Code docs that each behaviour rests on is in the Delegation table of p4-phi's README.

Every rule, call and line here is read from the plugin's source: phi.py, plans.py and the file in agents/, in ezexe/p4 under lbiza/plugins/p4-phi. The diagram is a model in your browser. Nothing on this page reaches a real session.
