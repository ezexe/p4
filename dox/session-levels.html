Session levels

Since version 0.9.0, p4-phi runs each piece of work at the level Claude Code gives it, so a session's own turn is never held by it. Choose a kind of task below, see the level it goes to, and step through the path its result takes back.

  • Sessions do the writing.A top session orchestrates and lands. Each work step of its plan goes to a child session, which the session tree page shows.
  • Subagents run in the background.The plugin ships three: p4-phi:sweep, p4-phi:runner and p4-phi:check. Any session can start one.
  • Nobody waits in the foreground.The session that asked goes on or ends its turn. A completion notification brings the result in a later turn.

The rewrite

A long command is a test_*.py run, pytest, unittest, or an npm, pnpm, cargo, go or make test or build. The plugin's PreToolUse hook reads every Bash and PowerShell call for one. Pick a call and a caller to see what the hook does with it.

The call

What the hook does


      

    

    
A top session's call is moved only when it is the long command and nothing else. Parts before the command may go to a folder or set a variable, and its output may pass through filters such as tail or grep. A call with a later part runs as sent, since the later part needs the command finished. So does a call that carries a timeout of its own, since the caller chose to wait. A child session's call is never changed: it gets the line once per plan step. A call that already has run_in_background: true is passed over, and a command the session's own records show as still running is not started a second time.

  


  

    
On by default

    
Nothing has to be configured. The levels rule, the three agents and the rewrite work in any project the plugin is enabled in.

    

      

        
Nothing to set up

        
    
          
  • Every session is given the levels rule at its start, beside the project's other standing rules.
    • 
          
  • The agents are files in the plugin's agents/ folder, so they load with the plugin under the names p4-phi:sweep, p4-phi:runner and p4-phi:check.
    • 
          
  • The rewrite works in a project with no .claude/p4 store. Top or child is then read from the app's record of the session.
    • 
          
  • Without a store, what a session was already told is kept in the plugin's data folder and removed after seven days unused.
    • 
        

      

      

        
One key turns it off

        
    
          
  • Set phi.levels to false in the project's .claude/p4/p4.json.
    • 
          
  • The levels rule is then left out, no long command is moved or remarked on, and plan steps are no longer named for a subagent.
    • 
          
  • No key turns it on. Any value but false, or no key at all, leaves it on.
    • 
        

        
{
 "phi": {
  "levels": false
 }
}
