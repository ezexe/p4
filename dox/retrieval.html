Retrieval

Beside each message of ezexe's and each subagent's task, p4-phi finds the few entries of the project's own history it is confident of, such as a rule, a correction, a fact, an earlier answer or a saved file, and by default passes on the rules and facts among them. It learns which entries help from what each turn used. This page says what the code does, each entry read from its source line.

The corpus

Retrieval ranks the entries a project keeps under its store's phi/store/, beside its auto memory and saved code. Every path here is under the project's .claude/p4/.

The files

rules.md, corrections.md, retractions.md and facts.md, with vocabulary.md for the dictionary and one file messages/<first 8 characters of the session id>.md for each session's message rows.

Each file opens with three header lines that name its fields: ruling, owner-words, scope, form, status, time and plain for a rule; key, time, match, meant and delta for a correction, or asked, time and omitted for a missed detail; freed, time, cause, owner-words, swept and lesson for a retraction; claim, source, verified, by, time, from and supersedes for a fact. The reader checks none of these fields.

An entry

An entry opens on a line - key: value at the left edge. Each further field is a line key: value indented two spaces, and a line indented four spaces carries on the field above it. Any other line ends the entry, which is how the header lines are passed over.

An entry's id

<file>:<time>:<first 8 hex digits of the SHA-1 of the entry's first value>, such as rules.md:2026-11-10 14:02:1a2b3c4d, with ~2, ~3 added to a second entry of the same base in one file. The id holds no line number, so an edit elsewhere in the file keeps it. A memory section is memory/<name>::<8 hex digits of its heading> and a saved-code head src/<path>::<8 hex digits of the path>.

Status

An entry is LIVE unless its own status: says SPENT, FREED or EXPIRED, or a retraction frees it. A retraction frees an entry with the same owner-words that is older than it or where either is undated, and one whose first value and the retraction's freed: text overlap so that the shorter, at least 24 characters long, is inside the longer. Retractions and message rows are never freed. Only LIVE entries are ranked.

The word a line starts with

A line names its entry's kind: rule, correction, missed detail for a correction with asked or omitted, retracted, fact, memory, earlier message or saved code. It reads - <date or undated> <kind>: <text> (<path>:<line>). A repository file prints - file: … and a commit - commit <date>: ….

The index

phi/models/index.json

One document for each LIVE entry of the four corpus files, each completed message row of ezexe's, each auto memory section, each saved-code head, and each repository or dependency document. It holds BM25 postings with document lengths, the table of short messages, each session's rows for the repeat line, the dictionary, the supersedes: pairs of facts and the rules by the minute they were written. index-cache.tmp beside it is a faster copy, and git ignores both.

When it is built again

When it is missing, of another version, older than any of its sources, or when the number of source files changed. Its sources are phi/store, temportal/memory, temportal/src, repo.json and deps.json.

Words

A word is a run of letters, digits and underscores that starts with a letter or underscore, or a dotted number such as 3.15. A word also yields its camel-case and snake-case parts. Each is lowercased and kept when it has three characters or more, a dot, or a letter and a digit such as p4, and is not a stop word.

What retrieval adds beside a message

The recall entry of p4-phi's hooks/hooks.json runs on each message of ezexe's, with a timeout of 10 seconds, and finds at most five lines for it. recall.inject in p4.json decides which of them reach the session: by default rules-facts, which passes only the lines of rules and facts and keeps the others in the served record for learning; true passes every line and false none, and P4_RECALL_INJECT set to 0, 1 or rules-facts wins for one run.

A short message

A message of at most five words that ezexe sent at least twice before, once answered, gets one line: - you have said "<message>" <N> times; last time (<date>) it was taken as: <answer>. Where the last three readings differ, the line names the two most frequent with their counts. No ranked line follows it, though the repeated-message line may.

A repeated message

A message that resembles an answered one of the same session, the same words or, from three words on, half of them shared, gets - an earlier message like this one (<time>) was answered: <answer>.

Ranked lines

The rest are ranked by BM25 over the message's words, with dictionary hits at half weight. With a trained ranker, a line prints when its score reaches the ranker's threshold. With none, the message's other word forms join at half weight, and a document prints when it holds at least two of the message's words, covering 75% of them and 65% of their weight, at a density of 0.35 per square root of its length; a file document may pass on looser gates of its own, a document the dictionary points at needs no gate, and one of the session tree's needs one shared word. On that road a rule written in the same minute as a correction or retraction takes that line's place. At most two lines come from one file and five in all, each cut to 160 characters.

Jargon

A line that holds a word of the store's own jargon, such as ruling, tombstone, read barrier or vlds, is dropped unless its entry has a plain: field, whose wording is then printed instead.

The session tree's words

With recall.node.on true in p4.json, up to 12 of the rarest words of this session's task and of the tasks and notes of the sessions above it join the query at weight 0.3, and the entries labelled for those sessions' tasks become candidates. It is off by default.

Rules every session holds

p4-phi hands no rules at a session start. Claude Code loads the rules files under .claude/rules/ and ~/.claude/rules/ itself. Source, memory.md: "Rules without paths frontmatter are loaded at launch with the same priority as .claude/CLAUDE.md." Source, context-window.md, the row "Project-root CLAUDE.md and unscoped rules | Re-injected from disk". A rule of rules.md an older copy marked pinned: yes is named to ezexe at a startup until a rules file or a memory holds its text.

Settings

The section recall.query of p4.json holds the numbers above: max_lines 5, per_file 2, text_chars 160, history_chars 120, candidates 200, min_rare 2, fallback_cover 0.75, fallback_icover 0.65, fallback_dense 0.35, file_shared 4, file_cover 0.55, file_dense 0.75, variant_weight 0.5 and expand_weight 0.5.

A failing hook

A retrieval hook of hook.py that raises an error exits 0 and adds nothing, with one line for ezexe, phi (p4-phi): the <name> hook failed with <error>; nothing was added, and one row a day in phi/models/retrain-needed.tsv for the p4-model skill.

Message rows

A row

Each message opens a row in its session's file with fingerprint:, the message cut to 300 characters, time: and arrival:, which is turn, notification or agent message. A turn's row names in resembles: the newest answered row it resembles.

Completed from the reply

When the turn ends, the row takes addressed:, the reply's first paragraph, and recommended:, its first recommending sentence. A row that resembled an earlier one is ECHO when the answers resemble each other too and SUPERSEDED when they do not, and a new one is FRESH. A notification's row is complete when it arrives.

Commands

Each runs as python -I -X utf8 "${CLAUDE_PLUGIN_ROOT}/scripts/p4.py" <command>, with --p4 <store> to name a store.

index

Builds the index again when it is stale, or always with --force, and prints index: rebuilt, <n> documents -> <path> or index: fresh. --repo first reads the project's tracked files and commits, and --deps its dependencies' documentation.

query --text "<message>"

Prints the lines retrieval would add, or the whole result with --json; --session gives the session for the repeat line.

check

Prints each corpus file's entries by status, the message rows, the dictionary, the labels and the index, ending on the share of indexed documents that hold jargon and no plain:, with a target under 10%.

How it learns

Each turn leaves labels: which documents of the index helped with which task. Rows go to phi/models/labels.tsv, labels-raw.tsv and tasks.tsv.

At a turn's end

The close hook on Stop completes the turn's message row, then labels each document retrieval served by whether the turn used it, and each repository file by what the turn did with it. It records the task, removes the served record and refreshes the index. It trains nothing.

After a subagent

The subagent-stop hook does the same for a subagent whose task retrieval served lines to, reading the subagent's own transcript.

Usage labels

A served document counts as used when the reply and the turn's edits and commands hold two of its rare words that the message did not, or a path it names that the message did not. Each such label weighs 0.3.

Repository labels

Each file a turn touched gets a label by what happened to it: edited 1 at weight 1.0, invoked 1 at 0.7, cited 1 at 0.7, dropped 0 at 0.3, unopened 0 at 0.2. A positive also reaches the file's symbols the turn named and its newest commit at half weight. p4.py labels --from-transcripts --slug <folder> labels the turns of earlier transcripts the same way, those of sessions with a message file unless --all-sessions, and replaces every repository row of labels.tsv, the hooks' rows included.

Other sources

p4.py labels --from-history labels a repeated short message on its earlier reading at weight 1.0, and store entries at 0.5. The migration imports labelled pools at 0.7. A label with no weight of its own reads at 0.7 for a pool, 0.5 for the store, 0.3 for usage and 1.0 otherwise.

Newer facts

A fact that supersedes: another takes over the older fact's positive labels for every task dated at or after it, or undated.

The train hook

Runs on Stop in the background, unless recall.learn is false, and trains only when a round is owed: the first label of a store, a dependency change since the last round, or ten new labels with the last round at least an hour old.

Training and evaluation

The ranker

phi/models/ranker.json is a logistic model in the standard library: 218 hashed features of each candidate, such as its BM25 score and rank, its file, kind, status and age, and how many of the message's rare words it holds, fitted by AdaGrad over 25 epochs.

p4.py train and eval

train runs one round, appends it to phi/models/eval.tsv and writes ranker.json only when the round is promoted, printing train: round N promoted or kept old with why. eval runs the same round and writes nothing. A round needs three labelled tasks with a positive among their candidates, and holds each out in turn up to 40, then uses five folds by time.

The threshold

The threshold is the one from 0.30 to 0.95 with the best mean F1 among those whose precision reaches 0.6, or the most precise one when none does, chosen on the labelled tasks alone.

Promotion

A round is kept old when its R-precision falls more than 0.02 below the last promoted round's, when its short-message rate falls, when its precision at the threshold is under 0.6, or when a dictionary entry that harms working messages stays on. Before any round is promoted, a store with at least three tasks labelled from pools alone needs those tasks to reach an R-precision of 0.36.

Silence tasks

Ordinary messages that should get no line, from phi/models/silent.jsonl or the plugin's silent-prompts.jsonl. Each candidate BM25 gives them is a negative, they train every fold, and the round reports the share the model would still print for.

Pool tasks

A task labelled from a pool keeps every candidate of the four corpus files, held entries included, so its negatives are the whole pool. Any other task keeps its positives and 60 negatives.

Settings

recall.train in p4.json: candidates 200, train_neg 60, folds 5, floor_drop 0.02, min_precision 0.6, first_floor 0.36, owed_labels 10, owed_age_s 3600, max_tasks 400.

The re-exploration measure

p4.py labels --reexploration counts, for each turn that opened a file it went on to use, the tool calls and input tokens spent before that file was opened, and how often the top five of retrieval held the file. It changes no label.

The teacher model

A larger model edits the labels of a batch of tasks through p4.py teacher, and its rows enter training as store+edited at weight 1.0.

The models

recall.teacher in p4.json names the teacher, claude-fable-5-2 by default, and the second opinion, claude-opus-5-5, with effort high and agree_min 0.65.

The cutoff

Each candidate newer than the teacher's training cutoff is marked [newer than your training], and up to 12 such entries that share a word with the task are sent beside it. The cutoff is --cutoff, else recall.teacher.cutoff, else the table in teacher.py, which knows only claude-opus-5-5's, 2026-06, and gives that to the others.

Stored facts

The prompt tells the teacher that a stored fact with verified: or checked: wins over its own knowledge, and shows each fact's verified, checked, since and prior fields. No code checks its answers against them.

The second opinion

--second-opinion N sends the newest N tasks to the second model. A batch whose two answers agree below an F1 of 0.65 is held in teacher-batches.json, and its tasks' own labels return to training.

Edited against raw

Each round with teacher labels fits once on the raw labels and once with the teacher's in their place, and scores both on the raw ones. A writing round that finds the teacher's worse holds those batches.

What a label records

labels.tsv has the columns task, entry, label, source, weight, time, teacher, edited, note: the teacher that answered and the date it edited. --re-edit sends again the tasks another teacher edited.

The dictionary

phi/store/vocabulary.md maps ezexe's own words to what they mean and the entries they point at.

An entry

term, means, means-by, because, source, points-at, added and status, on or off. One whose means is empty or starts (pending is pending.

Seeding

The migration writes one pending entry for the rarest word of ezexe's message before each correction, missed detail, retraction, repeat and follow-up. An entry whose first source is a follow-up starts off. The teacher fills the meanings.

Expansion

An entry that is on, not pending, and named in a message adds its meaning's missing words to the query at half weight, and the documents it points at pass the no-ranker road's word gates.

The check

Every round tests each entry that is on: a query on its quoted reason must rank what it points at in the top five, and it may change the top five of no more than 5% of 200 working messages. A failing entry is set off, unless its source holds the word owner: such an entry is listed and stays on, and keeps the round from promotion when it harms working messages.

Files and the migration

phi/models/

index.json, ranker.json, eval.tsv, the label files, teacher-batches.json, label-edits.md, spend.json, retrain-needed.tsv, and the indexes of the repository and its dependencies. ezexe/phi's p4-model skill writes the .pt ranker beside them.

Served records

phi/models/served/ holds one record of what retrieval served for each message, turn-<session>, and for each subagent's task, agent-<8 hex digits>, which the turn's end reads and removes. Records older than a day are removed at a session's start, and git ignores the folder.

p4.py migrate

Moves a store of the older layout into this one. It is a dry run unless --apply, writes its report to phi/archive/migration-<date>.md, and exits 1 on a failed check or an entry it could not place.

Each entry is read from hook.py, p4.py, store.py, rows.py, ranker.py, labels.py, train.py, teacher.py, migrate.py, node.py and p4conf.py of p4-phi, in ezexe/p4 under lbiza/plugins/p4-phi/scripts. The .pt ranker and the ensemble of shard models are ezexe/phi's, whose repository trains them.
