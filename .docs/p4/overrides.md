# The p4 overrides, measured

The plugins in `lbiza/plugins/` add contracts to every Claude Code session when it starts: the emission gate, the src-fragger contract, the VLDS memory override and the VLDS gc. They were written against earlier models. This note says how to measure whether each one still makes current models better than Anthropic's built-in behavior, and what to do with the answer.

**Run it:** [![Open in Colab](https://colab.research.google.com/assets/colab-badge.svg)](https://colab.research.google.com/github/ezexe/p4/blob/main/.docs/p4/overrides_colab.ipynb), then Runtime → Run all. The notebook is generated by `scripts/session/make_colab_notebook.py`; edit that, not the `.ipynb`.

## Method

The same shape as ezexe/phi's pathways notebook: each contract is a pathway, tested against controls, on several models and seeds, with every answer kept on Drive so a disconnect resumes.

| pathway | context in the first user turn |
|---|---|
| `builtin` | none: the built-in stand-in alone |
| `all` | every contract |
| `-<unit>` | every contract but that one |
| `+<unit>` | that contract alone |
| `pad` | neutral text as long as `all` |
| `~<unit>` | every contract, that one replaced by a measured rewrite |

`scripts/session/overrides_suite.py` runs one (model, seed). The tasks in `scripts/session/overrides_tasks.jsonl` cover code (with hidden tests), complete fences, honesty, simple questions (right and short), exact formats, and judgment calls (graded by a judge model). Protocol tasks, which check whether a contract's own convention shows, are reported apart. Every answer is also scanned for the contracts' own vocabulary, because a session that worked under all of them reported that words like "frag" and "ruling" leaked into what the user read.

Before anything is spent, every grader is checked against each task's reference and its bad answers (`--check-graders`). `python scripts/session/test_overrides_suite.py` tests the suite and the notebook's summary offline.

## Decisions

Per unit, over every model and seed:

- **keep**: it adds accuracy (with the others, or alone) and costs no category.
- **edit**: it adds accuracy but costs a category or plain language, or it adds nothing while its own convention shows. The notebook's editor rewrites it from the tasks it lost on the train split, and the rewrite is kept only if it scores at least as well on the test split, on every model and seed, and is shorter or scores higher.
- **drop**: it adds nothing anywhere.

## Limits

- `builtin` is a stand-in: Claude Code's own system prompt is not published whole.
- The calls are single-turn and have no tools, so the hooks that gate tool calls, and the operator's moments, are not exercised. Only the effect of a contract's text on an answer is measured.
- With about 26 general tasks, one task is about 4 points of accuracy. That is why a claim needs every seed to agree.
