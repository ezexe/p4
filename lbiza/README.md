# p4-marketplace

Claude Code plugins, each hooks and a script: they change where some files are stored, give the short-lived ones a lifetime, and add lines next to a message only when the repo's own history has something relevant. Claude Code and the desktop app keep working as they ship.

Each plugin writes only in its own directory under `<project>/.claude/p4/`: `temportal/` and `phi/`. Only `p4.json` and the store repository's own files stay at the top. A store an older version wrote flat in `.claude/p4/`, or under `recall/` while recall was a plugin of its own, is moved at the next session start by whichever plugin runs first, and the move is committed on its own. A file that differs between the two places keeps the newer copy, and the older one goes to `<plugin>/.layout-conflicts/`. A session's scratchpad link that pointed at the old place is pointed at the new one.

- **p4-temportal** keeps every file Claude Code would otherwise write under AppData or the system temp directory in `<project>/.claude/p4/temportal/`. It replaces p4-memory and p4-scratchpad.
  - `memory/` is Claude Code's built-in per-project memory, moved out of `~/.claude/projects/<slug>/memory/`. The AppData directory keeps one pointer `MEMORY.md`. At session start the hook prints the p4 `MEMORY.md` the way the built-in would print its own, plus one line when it moved a file or kept a conflict. A memory written into AppData is moved into p4.
  - `scratchpad/` is the notebook, tracked by the p4 repo. At session start it sweeps logs, build results and binaries into `scratchpad/.out/`, which ignores itself. Two asks about where code belongs ship off; `P4_SCRATCHPAD_ASKS=1` turns them on.
  - `tmp/<session>/` is each session's scratchpad: the session start turns the harness's per-session scratchpad into a link to it, a junction on Windows. Every turn's close stages it, and when the session ends it is committed, then deleted. `scratchpad.tmp` in p4.json, or `P4_SCRATCHPAD_TMP=0` for one run, turns it off.
  - `src/` is saved code the project repo does not use.
  - Lifetimes clear what is no longer relevant, as a browser does with its cache and cookies. A cache rule per directory in p4.json `temportal.cache` sets `max_age_days` and `max_mb`: `scratchpad/.out` keeps 14 days and 500 MB by default. A cookie is one file's own expiry, set with `hooks/lifetime.py set <path> 7d` and kept in `temportal/expires.json`; `session` as the lifetime clears it when that session ends. Expired files are cleared at each session start. `memory/` is never cleared. The plugin's `temportal` skill tells a session how to use it.
- **p4-phi** hands linked sessions their context: every session starts with the store's rules, a started session is given the tasks and notes of the sessions above it, ordered by its own task, and every finished turn's report reaches the session that started it. It also carries recall, the p4-recall plugin until p4-phi 0.7.0: a small ranker trained on the repo's own store, kept in `phi/store/` with its models in `phi/models/`, which adds a few lines from that history next to the owner's message or a subagent's task when it is confident, and nothing otherwise. Its hooks run as separate commands with their own timeouts, so recall keeps its own budget.

Every setting of every plugin lives in one file, `<project>/.claude/p4/p4.json`, one section per part (`memory`, `scratchpad`, `temportal`, `recall`). The first plugin to run in a project writes it with every default (seeded from the retired `models/config.json`, if any), and a newer plugin adds its new keys there, keeping every value already set; a value equal to its default leaves the code's own. `P4_SCRATCHPAD_ASKS` and `P4_RECALL_INJECT` still win for one run. The copies of `p4conf.py` in the two plugins are identical.

The design, with the measurements behind each part and the test plan, is [`.docs/p4/fresh-marketplace.md`](../.docs/p4/fresh-marketplace.md).

Tests: `python3 plugins/p4-temportal/hooks/test_p4_memory.py`, `python3 plugins/p4-temportal/hooks/test_scratchpad.py`, `python3 plugins/p4-temportal/hooks/test_lifetime.py`, and the `test_*.py` files of p4-phi.
