# p4-marketplace

Four Claude Code plugins. Three are hooks and a script each, with no skills, agents or commands: they change where some files are stored, and they add lines next to a message only when the repo's own history has something relevant. The fourth, p4-plans, is two skills and no hooks. Claude Code and the desktop app keep working as they ship.

- **p4-memory** stores Claude Code's built-in per-project memory in `<project>/.claude/p4/memory/` instead of `~/.claude/projects/<slug>/memory/`. The AppData directory keeps one pointer `MEMORY.md`. At session start the hook prints the p4 `MEMORY.md` the way the built-in would print its own, plus one line when it moved a file or kept a conflict. A memory written into AppData is moved into p4.
- **p4-scratchpad** keeps the notebook in `<project>/.claude/p4/scratchpad/`, tracked by the p4 repo. At session start it sweeps logs, build results and binaries into `scratchpad/.out/`, which ignores itself. It prints nothing unless it did something. Two asks about where code belongs ship off. `P4_SCRATCHPAD_ASKS=1` turns them on: a line for each file in `.claude/p4/src/` that the repo uses, and an ask before a code file is written to a temp directory or the notebook.
- **p4-recall** is a small ranker trained on the repo's own store: rulings, corrections, retractions, facts, earlier messages and memory. When it is confident, it adds a few lines from that history next to the owner's message or a subagent's task. Otherwise it adds nothing.
- **p4-plans** carries two skills. `plan-planner` keeps every plan in one directory while in flight, written once, tests first, with an evidence section that `check_evidence.py` holds to the tree, and closes it onto an archive branch; its `flight-ops.md` is the loop that flies a plan's sections as agents in the main checkout, kept apart by airspace. `sub-agentic` decides whether to delegate, how many agents, the shape said first, a model per role, the brief and the spend. A repository's own values (where plans live, its test commands, its model table, what to call the owner) go in the `plans` section of `<project>/.claude/p4/p4.json`; `skills/plan-planner/scripts/settings.py` prints them merged over the defaults.

Every setting of all four lives in one file, `<project>/.claude/p4/p4.json`, one section per plugin (`memory`, `scratchpad`, `recall`, `plans`). The first plugin to run in a project writes it with every default (seeded from the retired `models/config.json`, if any), and a newer plugin adds its new keys there, keeping every value already set; a value equal to its default leaves the code's own. `P4_SCRATCHPAD_ASKS` and `P4_RECALL_INJECT` still win for one run. The copies of `p4conf.py` in each plugin are identical.

The design, with the measurements behind each part and the test plan, is [`.docs/p4/fresh-marketplace.md`](../.docs/p4/fresh-marketplace.md).

Tests: `python3 plugins/p4-memory/hooks/test_p4_memory.py`, `python3 plugins/p4-scratchpad/hooks/test_scratchpad.py`, `python3 plugins/p4-plans/tests/test_p4_plans.py`.
