# p4-marketplace

Three Claude Code plugins, each hooks and a script, with no skills, agents or commands: they change where some files are stored, and they add lines next to a message only when the repo's own history has something relevant. Claude Code and the desktop app keep working as they ship.

- **p4-memory** stores Claude Code's built-in per-project memory in `<project>/.claude/p4/memory/` instead of `~/.claude/projects/<slug>/memory/`. The AppData directory keeps one pointer `MEMORY.md`. At session start the hook prints the p4 `MEMORY.md` the way the built-in would print its own, plus one line when it moved a file or kept a conflict. A memory written into AppData is moved into p4.
- **p4-scratchpad** keeps the notebook in `<project>/.claude/p4/scratchpad/`, tracked by the p4 repo. At session start it sweeps logs, build results and binaries into `scratchpad/.out/`, which ignores itself. It prints nothing unless it did something. Two asks about where code belongs ship off. `P4_SCRATCHPAD_ASKS=1` turns them on: a line for each file in `.claude/p4/src/` that the repo uses, and an ask before a code file is written to a temp directory or the notebook. The session start also turns the harness's per-session scratchpad into a link (a junction on Windows) to `<project>/.claude/p4/tmp/<session>/`, tracked by the p4 repo, moving in what it already held; the turn's close retries what the start could not do. A tmp is always staged and never deleted before it is committed: every turn's close stages the session's tmp in the p4 repo, and when the session ends the tmp is committed on its own, the files that commit holds are deleted, and the removal is committed too. A file no commit holds stays on disk: one the repo ignores, or one over `scratchpad.tmp_max_file_mb`. Another session's tmp left untouched for `scratchpad.tmp_idle_days` is closed the same way at a start, and a session that starts again gets its files back from the commit. `scratchpad.tmp` in p4.json, or `P4_SCRATCHPAD_TMP=0` for one run, turns it off.
- **p4-recall** is a small ranker trained on the repo's own store: rulings, corrections, retractions, facts, earlier messages and memory. When it is confident, it adds a few lines from that history next to the owner's message or a subagent's task. Otherwise it adds nothing.

Every setting of all three lives in one file, `<project>/.claude/p4/p4.json`, one section per plugin (`memory`, `scratchpad`, `recall`, `plans`). The first plugin to run in a project writes it with every default (seeded from the retired `models/config.json`, if any), and a newer plugin adds its new keys there, keeping every value already set; a value equal to its default leaves the code's own. `P4_SCRATCHPAD_ASKS` and `P4_RECALL_INJECT` still win for one run. The copies of `p4conf.py` in each plugin are identical.

The design, with the measurements behind each part and the test plan, is [`.docs/p4/fresh-marketplace.md`](../.docs/p4/fresh-marketplace.md).

Tests: `python3 plugins/p4-memory/hooks/test_p4_memory.py`, `python3 plugins/p4-scratchpad/hooks/test_scratchpad.py`.
